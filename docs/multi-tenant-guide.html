Architecture SaaS Multi-Tenant & Synchronisation

Principes de conception, isolation des données par établissement, Row Level Security (RLS) PostgreSQL et résilience hors-ligne totale.

1. Le Concept du SaaS Multi-Tenant Hybride

Study Agent Pro est conçu pour héberger un nombre illimité d'établissements scolaires en combinant une base locale SQLite ultra-véloce avec une base cloud Supabase centralisée :

  • Base Locale Isolée par École : Chaque installation locale génère une base SQLite dédiée (study_agent_<ecole_id>.db), garantissant qu'aucune fuite de données n'est possible sur la machine du client.
  • La Clé de Cloisonnement ecole_id : Chaque table métier (students, users, student_payments, cash_journal, cash_closures...) est liée à l'UUID de l'école.
  • Sécurité Absolue (RLS PostgreSQL) : La base de données PostgreSQL applique des politiques de Row Level Security. Une école ne peut sous aucun prétexte lire ou modifier les données d'une autre.

2. L'Installation chez un Client (Zero-Config)

  1. Premier Lancement : Le client lance l'exécutable (.exe). L'application détecte l'absence de base locale et affiche l'interface de Premier Démarrage (FirstBootOnboarding.tsx).
  2. Création du Compte Directeur : L'administrateur de l'école saisit son identifiant et son mot de passe sécurisé.
  3. Génération de l'Empreinte (UUID) : Le système génère automatiquement un UUID cryptographique unique qui devient le ecole_id de l'établissement.
Sécurité des Identifiants : Même si 50 directeurs d'écoles différentes choisissent admin comme nom d'utilisateur, la contrainte unique composite UNIQUE(username, ecole_id) garantit une coexistence 100% étanche sans aucun conflit.

3. Mécanisme de Synchronisation & Auto-Healing

La synchronisation fonctionne selon une stratégie Offline-First bidirectionnelle :

  • File locale sync_queue : Toute écriture locale (encaissement, inscription, clôture de caisse) est insérée dans la file d'attente locale avec horodatage.
  • Auto-Healing des Collisions de Matricules : Si deux caisses déconnectées attribuent le même numéro d'ordre, le moteur d'auto-healing détecte l'erreur PostgreSQL 23505, réattribue le numéro suivant pour cet ecole_id et valide la ligne.
  • Tolérance aux Déconnexions : En cas de perte réseau, l'application continue de fonctionner sans interruption et re-synchronise automatiquement dès le rétablissement de la liaison.
